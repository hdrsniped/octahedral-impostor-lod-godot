# tests — DOX

## Purpose
Every automated test and the runners. Each test is a `SceneTree` script that prints `PASS`/`FAIL` lines and ends with `RESULT PASS (n failures)` or `RESULT FAIL (n failures)` and quits with code 0/1. `visual_test.gd` is the exception: it prints `ACCURACY` lines (it is a measurement tool) and has a `--tag` for its output files.

- `run_all.sh` — the aggregate runner (63 entries: every test on Forward+, Mobile and Compatibility where it matters). Retries once when the log shows an engine allocation failure. Takes the Godot path as `$1` or `$GODOT`.
- `run_editor_test.sh` — the editor self-test. Copies `editor_selftest/scene_template.tscn.txt` to `tests/editor_tmp/scene.tscn`, enables `tests/editor_selftest/plugin.cfg` in `project.godot`, runs `--editor`, greps `SELFTEST`, restores `project.godot` and removes the temporary atlases. Set `EDITOR_LOG=<file>` to keep the full log.
- `cli_test.sh` — 10 CLI cases against `tools/octa_bake_cli.gd`.
- `editor_selftest/` — the in-editor scenario script and its plugin.cfg.
- `fixtures/` — old-format atlases (`v1_all.res`, `v2_all.res`, `v2_plain.res`, `v2_fmt2.res`), the reference renders under `fixtures/refs/<renderer>/`, `make_fixtures.gd` and `compat_render.gd` to regenerate them. The folder has a `.gdignore` so Godot does not import the PNGs.
- `out/` — logs and screenshots written by the tests (git-ignored). Never commit anything from here.
- `scratch/` in the test copy (not in the repo) — throwaway probes for measurements; delete after use and never sync it back.

## Local Contracts
- One Godot process at a time on this machine (a second test run would steal the GPU): take the lock `D:\Gamedev\Projects\navis\godot.lock` before syncing or running (create it; if it is younger than 15 minutes wait 30 s and retry; older, delete and take over) and remove it in a `finally` block.
- Tests run on the scratch copy `D:\Gamedev\Projects\navis\oil`, never in the master tree (the owner may have the editor open there). Sync with `robocopy "<repo>\addons" "...\oil\addons" /MIR /NFL /NDL /NJH /NJS /NP`, the same for `tests`, `demo`, and copy `project.godot`; then `godot --headless --path . --import` (needed after new/renamed class files; the `.uid` files are generated by this).
- Tests need a window; they hang with `--headless`. Always give a Godot run a timeout (the runners use 600 s per test): a test that awaits `RenderingServer.frame_post_draw` waits forever when the window stops drawing, and that stall is environmental.
- A test must clean up after itself: free its nodes, delete any `user://` file it created, and not leave atlases in `octa_impostors/`.
- Baselines that must not regress: editor self-test **137 PASS / 0 FAIL**; `cli_test.sh` **RESULT PASS** (10 cases, including `--pack`); `run_all.sh` **60 RESULT PASS** (the six `visual` entries print ACCURACY only); `compat_test` **0 differing pixels** on each renderer.
- Recorded accuracy baseline (Forward+, default settings): Rock High MAE 8.09 / bad 7.35%, Rock Ultra 7.17 / 6.62%, Tree High 4.95 / 9.23%, Rings High 15.05 / 26.14%. A change that moves these must be intended and recorded.

## Work Guidance
- New test: a `SceneTree` script that prints `PASS`/`FAIL` with a clear subject, ends with `RESULT`, exits non-zero on failure, cleans up, and is added to `run_all.sh` (all three renderers if it renders).
- New feature: the test must prove both sides — the feature working and the off path being identical (`bad px`/pixel-compare against the shipped behaviour).
- Use `tests/test_rig.gd` (`TestRig.make/shoot/grab/compare/difference/interior_difference`) for render comparisons; it uses 256x256 SubViewports with 4x MSAA.
- Flaky by design (environmental, not code): `demo_compat` can stall at startup (retry once), `queue_mobile` can exceed its max-frame limit under load, `transform_compat` timed out once in a long run. Re-run before calling a regression.
- Do not print raw debug output in a test that is in `run_all.sh`; use the `PASS`/`ACCURACY`/`RESULT` vocabulary so the runners can grep it.
